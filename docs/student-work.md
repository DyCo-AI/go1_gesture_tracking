# Student work and experiment data

Each student submits a `README.md` each week on the assigned `team-alpha` or
`team-bravo` branch of the student code repository:

```text
course/student-work/<team>/<first-last>/week-XX/README.md
course/student-work/<team>/<first-last>/final-report/README.md
```

Use your own student folder; no personal branches are needed. Reports contain
goals, worksheet answers, results, limitations, lessons, and next steps. Weekly
deliverables are report content, not requests to upload code or raw experiment data.
Code experiments stay local unless the instructor explicitly requests a contribution.
Previously submitted weekly-summary files can stay in place.

Optional short compressed MP4/GIF evidence belongs in `week-XX/media/`: default
limit **5 MB per file and 10 MB per student per week**. README-only is sufficient.
Keep full run ZIPs, telemetry, raw videos, and replay data locally with a backup.
Reference run IDs and concise results in reports; arrange any data transfer with
the instructor. Use those local data for the end-of-course Markdown report.

The maintained [submission/data policy](https://github.com/sriram-2502/go1-mujoco-playground/blob/main/course/SUBMISSIONS.md)
has the exact folder conventions, media rules, and storage guidance. Copy the
[weekly README template](https://github.com/sriram-2502/go1-mujoco-playground/blob/main/course/WEEKLY_REPORT_TEMPLATE.md).

Ask the instructor for the robot-specific AES key and Wi-Fi credentials; never
include them in reports, screenshots, code, or Git. Install software using internet
first, then join the **Go2 Wi-Fi hotspot** for the robot connection at **192.168.12.1**.
Do not use Clemson campus Wi-Fi for robot access; firewall/client isolation can
interfere. Do not disable security controls as a workaround. Follow the
[Go2 hardware guide](https://github.com/sriram-2502/go1-mujoco-playground/blob/main/course/GO2_HARDWARE.md).
